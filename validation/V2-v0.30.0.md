# V2 runtime validation — 2026-09-30

The experimental adapter on `v2-support` was tested with real Qwen3.5-0.8B
BF16 inference on CPU. Eager and compiled V2 both pass the mixed-traffic
comparison with V1 and the long-prompt HTTP suite. The short image case fails
the independent Transformers tolerance on both V1 and V2; this is not a fully
passing numerical certification. Eager MTP also passes target-state comparison
with non-MTP V2 while actually drafting and accepting tokens. These runs preceded
the subsequent removal of the launcher's V1 default; runner selection now
follows upstream defaults and the caller's environment.

## Launcher follow-up

After these inference runs, `serve.py` stopped setting or validating
`VLLM_USE_V2_MODEL_RUNNER`. The launcher now inherits upstream defaults and any
caller selection. All 49 startup tests and targeted Ruff checks passed after
that change. The 113-test runtime-era count below is historical: one obsolete
invalid-runner test was subsequently removed. No new model inference was needed
for the pass-through environment change; the server runs below explicitly
selected their runners.

## Results

| Check | Result |
| --- | --- |
| Adapter, lifecycle, launcher, and existing unit tests | 113 passed, 15 warnings |
| V1 real control: six short/long text/image cases and mixed traffic | Pass; repeated vectors identical; 6,400 prefix-hit tokens |
| V2 plugin-disabled eager and compiled ordinary baselines | Pass, short and long |
| V2 eager and compiled mixed extraction/generation, compared with V1 | Pass within unchanged cosine ≥ 0.999 and relative L2 ≤ 0.05 thresholds |
| V2 eager and compiled long-prompt Transformers/HTTP suite | Pass, including actual chunking, concurrency, prefix hits, ordinary-response parity, streaming, and invalid-request rejection |
| Eager V2 MTP ordinary baseline, target-state/mixed-traffic comparison, and long HTTP suite | Pass; 49 draft tokens, 27 accepted tokens in the mixed suite |
| Short text Transformers comparisons | Pass in eager and compiled V2 |
| Short image Transformers comparison | **Fail** in both V1 control and V2; details below |

Long prompts contain 1,628 text tokens or 1,705 image/text tokens, exceeding the
1,280-token scheduling budget. Each non-MTP long HTTP suite measures **14,080
prefix-cache hit tokens** (7,040 with MTP). The mixed-traffic suite combines ordinary 16-token
generation with six extraction requests. All vectors contain 1,024 finite values.
The HTTP suite checks prompt IDs/positions, first generated token, one-token
usage, ordinary choices/usage/prompt IDs against the plugin-disabled V2 baseline,
and ordinary streaming. Extraction with `max_tokens=2`, `n=2`, or `stream=true`
returns HTTP 400. The short suite stops at its image failure; the complete long
suite establishes the later protocol checks.

CPU compiled runs use `DYNAMO_TRACE_ONCE` with Inductor. Both baseline and plugin
server logs record saving an AOT-compiled model during warmup; compilation was
not bypassed. CPU graph mode is `NONE`, so these results say nothing about CUDA
graph replay. The plugin launcher was invoked without an executor argument;
its automatic `mp` selection works in these real runs.

| Numerical comparison | Eager V2 | Compiled V2 |
| --- | --- | --- |
| Minimum cosine vs V1, six cases | 0.999531 | 0.999543 |
| Maximum relative L2 vs V1 | 3.068% | 3.026% |
| Maximum relative L2 under repeated/mixed traffic | 1.320% | 0.887% |
| Maximum relative L2 vs Transformers, complete long suite | 3.125% | 2.668% |

### Short image discrepancy

The same 105-token image prompt has matching prompt IDs, final prompt position,
and first generated token in all comparisons, but its vector exceeds the
pre-existing strict thresholds:

| Runner | Cosine vs Transformers | Relative L2 |
| --- | --- | --- |
| V1 eager control | 0.998545 | 5.400% |
| V2 eager | 0.998052 | 6.248% |
| V2 compiled | 0.997909 | 6.469% |
| V2 eager MTP | 0.998031 | 6.281% |

The failure also occurs with V1, so it is not unique to the new V2 adapter.
That does not establish its precise kernel-level cause or make V2's larger
error acceptable. Thresholds were not relaxed. Keep this numerical gap visible
when deciding whether to promote V2 beyond experimental status.

### MTP target/draft isolation

The MTP runs use `--speculative-config '{"method":"mtp","num_speculative_tokens":1}'`.
The ordinary plugin-disabled MTP server passes short and long requests. The
plugin mixed-traffic run uses `validate_mtp.py --require-mtp`, comparing with
the non-MTP V2 eager snapshot. Its measured counters are **49 draft tokens and
27 accepted tokens**; enabling the flag without actual drafting would fail.

All six extracted vectors match the non-MTP control within unchanged tolerance
(minimum cosine 0.999854, maximum relative L2 1.711%). Ordinary generated token
IDs also match that control, and ordinary streaming succeeds. The long HTTP
suite passes against Transformers and the plugin-disabled MTP baseline. The
short image independently fails as shown above. These results support target
state capture before draft execution in this tested configuration; compiled
MTP and GPU MTP remain untested.

## Reproduction and artifacts

The [run directory](runs-v2-v0.30.0) contains exact command arrays and environment
overrides (`*-commands.json`), server output, helper output including failed
assertions, and successful JSON metric reports. Raw reference and response
vectors remain in `/tmp`; regenerate them with the existing helpers when needed.

From the package root, use the isolated interpreter or an equivalent native
vLLM 0.30.0 CPU environment with Triton CPU:

```sh
export PYTHONPATH="$PWD:$PWD/vllm" HF_HUB_OFFLINE=1
export VLLM_USE_RUST_FRONTEND=0 VLLM_USE_V2_MODEL_RUNNER=1
export VLLM_CPU_KVCACHE_SPACE=1 VLLM_CPU_OMP_THREADS_BIND=nobind
export OMP_NUM_THREADS=8 VLLM_WORKER_MULTIPROC_METHOD=spawn VLLM_PLUGINS=''
validation_python=/tmp/vllm-v2-runtime/bin/python
validation_model=/home/soren/.cache/huggingface/hub/models--Qwen--Qwen3.5-0.8B/snapshots/2fc06364715b967f1860aea9cf38778875588b17
"$validation_python" validation/validate_hidden_state.py reference \
  --model "$validation_model" --reference /tmp/vllm-v2-reference.json
"$validation_python" validation/validate_hidden_state.py reference \
  --model "$validation_model" --long-prompts --reference /tmp/vllm-v2-reference-long.json
"$validation_python" -m vllm_last_hidden_state.serve "$validation_model" \
  --host 127.0.0.1 --port 18430 --dtype bfloat16 --max-model-len 4096 \
  --max-num-batched-tokens 1280 --max-num-seqs 4 --skip-mm-profiling \
  --enable-chunked-prefill --enable-prefix-caching --enforce-eager
```

For the ordinary baseline, replace the module with
`vllm.entrypoints.cli.main serve` and add `--distributed-executor-backend mp`.
For compiled runs omit `--enforce-eager`. Run `validate_hidden_state.py baseline`
and `http` with matching reference files, adding `--long-prompts` and
`--require-prefix-cache-hit` for the long HTTP run. Exact helper arguments are
in the command artifacts. `validate_mtp.py` without `--require-mtp` supplies the
six-case mixed-traffic snapshot comparison; its name does not imply that those
non-MTP runs used a drafter.

The CPU backend was built from `https://github.com/triton-lang/triton-cpu.git`
at `270e696d` with its submodules initialized, then installed only into the
isolated environment:

```sh
# From the pinned triton-cpu checkout; LLVM_SYSPATH is optional if allowing
# its build helper to download the same pinned toolchain automatically.
UV_CACHE_DIR=/tmp/vllm-v2-uv-cache TRITON_HOME=/tmp/vllm-v2-triton-cache \
  LLVM_SYSPATH=/tmp/vllm-v2-llvm/llvm-87717bf9-ubuntu-x64 MAX_JOBS=16 \
  uv build --python /tmp/vllm-v2-runtime/bin/python \
  --wheel --out-dir /tmp/vllm-v2-wheels
UV_CACHE_DIR=/tmp/vllm-v2-uv-cache uv pip install \
  --python /tmp/vllm-v2-runtime/bin/python \
  --target /tmp/vllm-v2-runtime/lib/python3.12/site-packages --no-deps \
  /tmp/vllm-v2-wheels/triton-3.7.0+git270e696d-cp312-cp312-linux_x86_64.whl
```

The unit suite is run from the package root with:

```sh
HF_HUB_OFFLINE=1 PYTHONPATH="$PWD:$PWD/vllm" \
  /tmp/vllm-v2-runtime/bin/python -m pytest -q
```

## Remaining scope

CUDA eager/graph execution and async scheduling, compiled MTP, real scheduler preemption and
client cancellation, quantized V2 inference, other checkpoint sizes, and other
hardware remain unvalidated here. Lifecycle unit fixtures cover some of these
mechanics but do not replace runtime evidence. All seven test servers exited
with code zero and were confirmed stopped. No implementation fix was required
by these runs; this follow-up adds validation evidence and updates status
documentation. No code was pushed or committed.
